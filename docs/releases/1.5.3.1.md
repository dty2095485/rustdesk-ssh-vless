## Changes

### Upstream 1.5.1 → 1.5.3

- New: request approval as a login method, trusted devices for direct-IP
  connections, greetd Wayland login screen over DRM.
- Windows: main-IPC authorization, installer directory guards, the named-pipe
  installer handoff that F-Secure blocked is gone, service IPC is retried before
  the GUI is terminated, the clipboard owner marker is written first.
- Other fixes: still screens are no longer re-encoded on DRM, port-forward KCP
  handle lifetime, relay only to addresses the peer offered, sensitive options
  blocked in strategy updates.

### Fork

- No feature changes. Every fork feature from 1.5.1.5 is carried over: VLESS /
  VLESS+REALITY / SSH transport, Windows clipboard fast channel, No Displays hold
  and session-switch retry, RDP rendering fallback, installer double-click
  install, server-side online status.
- The clipboard fast channel's hidden connection passes the new upstream
  `login_method` argument as automatic login (it reuses the parent's token and
  must never ask for approval).
- Source now comes from upstream `1.5.3` plus a linear patch series (one commit
  per fork feature, `scripts/upstream/`); about 50 upstream files that only
  differed by formatting or file mode are byte-identical to upstream again.

## Verification

- `scripts/upstream/check_patches.py`: 15/15 fork features present.
- `cargo check` (lib `flutter,inline,vram,hwcodec`; bins `inline,vram,hwcodec`)
  and the release build: no errors. `dart analyze lib`: 0 errors.

## Known limits

- **Not tested on a real device or with `rdtest_e2e.py` before release.** In
  particular VLESS/SSH connections, clipboard file transfer over the fast
  channel, "No Displays" after RDP session switches, and the service under the
  new upstream Windows IPC authorization are only build-checked.
- Android and Docker are not rebuilt; use 1.5.1.2 (Android) and the 1.5.1.5
  server image.
